# Отчёт владельцу: этап 1, кухня в треде (2026-10-28)

Задача — `docs/start/TASK_FIRST.md`. Ядро modulero-next `cbaf1534`, каталог `hw-2026-10-27.8` (AI-DEC-003), без Claude API и без публикации (AI-DEC-001). Всё, помеченное (Д), — предложение, а не решение.

## Итог
Стенд работает: помощник в треде ведёт диалог «Хочу кухню» только вызовами движка, после каждой правки строится страница прототипа (превью, план, развёртки стен, состав, цена «полная / неполная», варианты, история, лента диалога, расход Claude API). Пример `EXCHANGE_SPEC.md` §6 на стенде даёт те же ревизии `KPR2-…` и суммы, что `reference/start/examples/kitchen-dialog.log.json`. 12 сценариев записаны из настоящих диалогов в треде и проигрываются `npm run check` без ИИ.

## Как попробовать
Открыть тред проекта и написать «Режим диалога», затем «Хочу кухню». После каждого ответа помощника — ссылка на частную страницу прототипа и строка расхода через Claude API (оценка). Выход — «Выйти из режима диалога».

## Что сработало
- Договор `EXCHANGE_SPEC.md` годится как есть: шесть инструментов и `offer_choices` / `open_in_editor` покрыли все 12 сценариев; закрытый список правок и отказ движка словами не дают ИИ «досчитать» сам.
- Одна реплика — один `kitchen_edits` — одна версия; `base_revision` ловит устаревшую версию (`STALE_REVISION`).
- Цена: стенд отдаёт только итог, известную часть и чего не хватает; себестоимость, ставки и наценки в ответ не попадают (k11, k12). Проверка `answerProblems` в `npm run check` ловит в ответе помощника сумму не из ответа стенда, скрытую неполноту и больше трёх вопросов.
- Отмена и варианты (k10) работают через черновик ядра; файл каждой версии `.modulero` открывается в конструкторе.

## Что мешает
1. Движок не говорит, где на стене свободно, и сам не находит место без `pos` (k02, k03, k04, k06, k07). ИИ угадывает положение или пробует несколько раз.
2. Отказы называют не ту стену («На стене B» про основную) и не тот модуль (m4 вместо m5) — ИИ приходится пересказывать по смыслу, а не по словам.
3. Ограничения карточек не видны заранее: сушка только в шкаф 600, ширина посудомойки меняется только заменой модуля (k01, k07).
4. В `price.missing` приходят условия мебельщика (проценты сборки и наценки) и внутренние номера строк сметы. Стенд прячет условия и считает их в `terms_hidden` (Д), но правильнее, чтобы ядро отдавало сводку «для экрана».
5. Нет правки «поменять местами» / «переставить»: цепочка «удалить → перенести → добавить» может упасть на середине и оставить промежуточную версию (k02).
6. Кухня длиннее 4 м — пути нет (k08).

## Правила помощника (Д, `SYSTEM_PROMPT_DRAFT.md`)
- В пакете правок сначала то, что не может отказать (размеры, материалы), потом модули: первый отказ останавливает остальные (k06).
- Не добавлять модули, которых человек не просил (k02); после сбоя цепочки перестановки сразу вернуть снятый модуль.
- О материалах и декорах — только по `get_options` (k10, k12); если точного декора нет — предложить 2–3 близких кнопками.
- Расстояния («около 20 см») не считать самому — ждать сводку свободных участков (k07, MOD-AI-8).
- При покупных фасадах оговаривать, что известная часть цены уменьшилась не потому, что кухня дешевле (k09: 141 → 111 тыс. ₽).
- В списке вариантов показывать человеку только сохранённые по имени (k10).

## Когда подключать API
Не раньше, чем (а) пройдены сценарии этапа 2 и (б) в Modulero есть хотя бы MOD-AI-3, MOD-AI-4 и MOD-AI-8: без них ИИ через API будет делать лишние вызовы и пересказывать путаные отказы — это деньги и качество. Тогда первый шаг — тот же стенд с настоящими вызовами Messages API на проигрыше 12 + 30 сценариев, с замером `usage` против оценки AI-DEC-006; сайт — после этого и только решением владельца (этапы 3 и 4).
