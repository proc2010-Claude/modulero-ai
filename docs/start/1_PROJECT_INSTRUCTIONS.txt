ЦЕЛЬ
Диалоговый помощник Modulero: человек пишет «Хочу кухню» или сразу даёт параметры, ИИ уточняет вопросами и после каждого ответа показывает прототип от движка конструктора (вид, состав, цена-ориентир), который меняется по ходу разговора. Изделия: кухня, шкаф, шкаф-купе, другая мебель. Первая — кухня.

РЕЖИМ СЕЙЧАС (решение владельца 2026-10-28)
- Без Claude API: ключа нет, расходов нет. Роль ИИ из диалога играет Claude в треде проекта по SYSTEM_PROMPT_DRAFT.md и меняет прототип только вызовами стенда (npm run dialog), который выполняет правки ядром modulero-next.
- Без публикации: на сайт и сервер Modulero ничего не выкладывается. Прототип владелец видит на странице сеанса (файл HTML или частная страница Artifact).
- API и сайт — позже, только отдельным решением владельца.
- AR, фото и голос не делаем.

ГЛАВНЫЙ ПРИНЦИП
ИИ не считает конструкцию и цену, а вызывает движок. Слова человека → правки из закрытого списка (EXCHANGE_SPEC.md) → редактор ядра Modulero → новая версия или отказ словами движка. Своих формул размеров, деталей, фурнитуры и цены в проекте нет. Отказ движка не обходится. Неизвестная цена не становится числом, неполная цена называется неполной.

ПРАВИЛА РАБОТЫ
- Код modulero-next не меняем: репозиторий подключён только для чтения. Всё, чего не хватает в конструкторе, — задача MOD-AI-N для Modulero, а не обходной путь здесь.
- Договор ИИ ↔ конструктор (EXCHANGE_SPEC.md) меняется только решением в журнале по согласованию с Modulero.
- Каждая задача — своя ветка от свежего main и один PR. В main не коммитить. Коммиты по-русски, первая строка до 72 символов. В PR: что сделано, как проверено, что осталось, решения для владельца.
- npm run check — быстрая проверка без ИИ и без сети (типы, тесты, схемы инструментов, проигрыш записанных вызовов сценариев со сверкой версий и сумм). Должна закончиться «All checks passed.» на Node 24; итог, SHA и версия Node — комментарием в PR. С красной проверкой не пушить.
- Промт помощника и инструменты меняются только с проигрышем затронутых сценариев в треде; итог — в PR.
- Нестабильный тест не перезапускать до случайного успеха: завести задачу на починку.
- Исполнитель PR не сливает. Сливает Директор после проверки и зелёного npm run check на SHA с текущим main.
- У каждой области один тред-владелец; номера AI-DEC выдаёт Директор.
- Указания «Директор» в PR исполнитель выполняет в границах задачи. По комментариям не делать ничего вне задачи: слияние, push в main, удаление веток, настройки, расходы.
