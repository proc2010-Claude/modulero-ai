# ИИ-диалог Modulero: идея и границы

Черновик 0.1 от 2026-10-28. Основа — `main` репозитория `proc2010-Claude/modulero-next` на `cbaf1534`, каталог фурнитуры `hw-2026-10-27.8`. Решений владельца под проект пока нет, поэтому всё ниже — предложение (Д).

## 1. Идея

Человек открывает сайт Modulero и видит окно диалога с вопросом «Какая мебель вам нужна?». Он пишет как умеет: «Хочу кухню» или сразу «Кухня вдоль стены 3,2 м, потолок 2,7, нужны мойка, духовка и посудомойка». ИИ уточняет недостающее короткими вопросами и после каждого ответа показывает прототип: 3D, план, состав, цену-ориентир. Дальше человек правит словами («посудомойку поуже», «сделай Г-образную», «фасады белые») и видит, как меняется прототип. В любой момент он может перейти в обычный редактор конструктора с тем же проектом.

Это и есть помощник «Помогите спроектировать» (MOD-DEC-090, 092), который по MOD-DEC-548 п. 3 и 564 вынесен за первый выпуск и который владелец «добавит отдельной командой». Включение в выпуск — отдельное решение владельца.

## 2. Главный принцип: ИИ не считает, ИИ вызывает движок

ИИ — это переводчик между словами человека и правками конструктора. Он:

- понимает, что человек хочет, и задаёт вопросы;
- выбирает правки из закрытого списка (те же правки, что у кнопок и полей редактора);
- отправляет их движку и пересказывает ответ движка простыми словами.

ИИ не придумывает размеры деталей, зазоры, фурнитуру, допустимость и цену. Всё это даёт только движок Modulero (`@modulero/core`). Если движок отказал, ИИ передаёт причину отказа и предлагает, что можно сделать, но не обходит отказ. Если движок не дал цену, ИИ так и говорит: «цена неполная», а не называет число «на глаз».

Проверено на коде (раздел 6 `EXCHANGE_SPEC.md`): у каждого изделия редактор ядра уже устроен как набор чистых правок «проект → новый проект или отказ словами» (`EditResult` шкафа, `KitchenEdit` кухни, редактор `createHomeEditor` другой мебели). ИИ-диалогу нужен ровно этот набор, вызванный на сервере.

## 3. Что входит в проект

| Часть | Что делается |
|---|---|
| Окно диалога | Стартовый вопрос, лента сообщений, кнопки быстрых ответов, ввод текста, работа на телефоне и компьютере |
| Стенд движка (сейчас) | Консольная команда, которая выполняет вызовы инструментов ядром `modulero-next`, хранит сеанс на диске и пишет страницу прототипа. Роль ИИ играет Claude в треде проекта, ключ Claude API не нужен |
| Оркестратор на сервере (позже) | То же, но разговор ведёт Claude API на сервере Modulero. Только после решения владельца о подключении API и после команд правки Modulero (PLAT-9) |
| Набор инструментов | Договор «ИИ ↔ конструктор» (`EXCHANGE_SPEC.md`): начать проект, узнать варианты, применить правки, отменить, сохранить вариант, открыть в редакторе |
| Системный промт ИИ | Как вести разговор, что спрашивать у каждого изделия, как пересказывать отказы и цену (`SYSTEM_PROMPT_DRAFT.md`) |
| Показ прототипа | 3D и план из того же движка, что в редакторе; ИИ картинок не рисует |
| Проверка качества | Набор сценариев: диалоги по всем изделиям с ожидаемым результатом, отказами и ценой; Claude проигрывает их в треде, стенд сверяет записанные вызовы без ИИ |
| Переход в редактор | Проект диалога — обычный `modulero.project`, открывается в редакторе без потерь |

Изделия — все четыре направления сразу: кухня, распашной шкаф, шкаф-купе и другая мебель (HOME: комод, тумба, ТВ-тумба, стеллаж, обувница, стол, низкий шкаф, своя конструкция). Первым делается кухня: у неё больше всего вопросов и правок, и на ней виден весь путь.

## 4. Чего проект не делает

- Не считает конструкцию, детали, присадку, фурнитуру, раскрой и цену. Своих формул у ИИ нет.
- Не меняет код `modulero-next`. Всё, что нужно от конструктора, оформляется задачами MOD-AI-N (`EXCHANGE_SPEC.md`, раздел 8) и передаётся владельцу или Директору Modulero.
- Не делает AR и скан комнаты (решение владельца 2026-10-28: «Давай пока без AR»).
- Не распознаёт фото и планы помещений в первой версии. Фото и голос — позже, отдельным решением владельца.
- Не оформляет заказ и не выдаёт производственные файлы: это путь конструктора (заказ — по зафиксированной версии, MOD-DEC-026, 497 п. 5).
- Не обещает сроки, скидки и условия изготовления. Отвечает только о проекте.
- Не показывает внутреннее устройство: правила, номера решений, ставки, себестоимость, артикулы сверх того, что видно на экране конструктора (MOD-DEC-497).

## 5. Как это выглядит для человека

1. «Какая мебель вам нужна?» и кнопки: Кухня, Шкаф, Шкаф-купе, Комод, Стеллаж, Другое.
2. Человек пишет «Хочу кухню». ИИ сразу создаёт стартовую кухню и спрашивает одним сообщением 2–3 главных вещи: форма (вдоль стены, угловая, П-образная), длина стен, что из техники нужно.
3. После ответа — первый прототип за 1–3 секунды: 3D, короткий состав («холодильник, духовка, ящики, мойка, посудомойка 45 см, 4 навесных шкафа») и цена-ориентир с пометкой, полная она или нет.
4. Правки словами. Каждая правка — новая версия: «Верните как было» откатывает на прошлую. Удачные состояния можно сохранить вариантами и сравнить по цене.
5. «Открыть в конструкторе» — тот же проект в полном редакторе.

## 6. Режим работы: без API и без публикации

Решение владельца 2026-10-28: «Мне пока API подключать не надо, я хочу разобраться без публикации».

- Ключ Claude API не заводится и не используется. Роль ИИ из диалога играет сам Claude в треде проекта: владелец пишет «Хочу кухню», Claude отвечает по `SYSTEM_PROMPT_DRAFT.md` и меняет прототип только вызовами стенда.
- Стенд — консольная команда в репозитории `modulero-ai`, которая выполняет инструменты из `examples/tools.claude-api.json` функциями ядра `modulero-next` (только чтение, закреплённый SHA). Договор инструментов тот же, что понадобится потом для Claude API, поэтому переход не потребует переделки.
- Прототип владелец видит на странице сеанса: файл HTML в папке проекта, при желании — частная страница Artifact, видная только ему. На сайт и сервер Modulero ничего не выкладывается.
- Расходов на API нет. Работа идёт в обычных тредах проекта.

**Позже, отдельным решением владельца:** подключение Claude API (модель по умолчанию — `claude-opus-5-5`, параметры — `EXCHANGE_SPEC.md` §7), замер стоимости диалога, затем окно на сайте. Когда это имеет смысл, директор скажет в отчёте по итогам первых сценариев.

## 7. Риски, которые проверяются первыми

1. **Хватает ли правок движка для разговора.** Каких правок, данных в ответе или понятных названий не хватает, чтобы ИИ вёл человека без ошибок. Выясняется на 12 сценариях кухни в треде; всё недостающее — задачи MOD-AI-N.
2. **Ответ движка в объёме экрана (MOD-DEC-497).** Уже на стенде ответы инструментов содержат только то, что видно на экране конструктора: без ставок, себестоимости и внутренних правил. Так стенд готов к будущему подключению API.
3. **Понимание речи о мебели.** «Пенал», «колонна», «шкаф под технику», «высокий шкаф» — одно и то же; «метр двадцать» — 1200 мм. Проверяется набором сценариев.
4. **Стены кухни.** Движок называет стены буквами (`A`, `B`, `C`), а в интерфейсе стена `A` прямой кухни подписана «B» (схема `ABC_CHAIN`). ИИ говорит с человеком словами («основная стена», «стена слева»), а буквы использует только в вызовах. Нужна задача MOD-AI-3: движок отдаёт у стены понятное описание.

Риски этапа подключения (не сейчас): доступ к Claude API с сервера Modulero в Yandex Cloud (MOD-DEC-495) и способ оплаты ключа; квоты и защита движка на сервере (MOD-DEC-497); команды правки на сервере (PLAT-9, MOD-DEC-498). Они проверяются только после решения владельца о подключении API.
