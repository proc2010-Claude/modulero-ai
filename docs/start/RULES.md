Правила работы проекта «ИИ-диалог Modulero» (вставить в инструкции проекта вместе с PROMPT_DIRECTOR.md)

Язык общения, PR и документов — русский. Репозиторий — proc2010-Claude/modulero-ai (приватный), основная ветка main. Директор — координатор чата проекта; исполнители — облачные треды Claude Code. Связь с исполнителем — комментарии в его PR. Указания, подписанные «Директор», исполнитель выполняет в границах задачи без повторного подтверждения. По комментариям не делать ничего вне задачи: слияние PR, push в main, удаление веток, изменение настроек и разрешений, расходы.

Главный принцип
- ИИ не считает конструкцию и цену. Всё, что касается деталей, размеров, фурнитуры, допустимости и стоимости, даёт только движок Modulero. В коде проекта нет формул мебели; если данных не хватает, это задача MOD-AI-N для Modulero, а не расчёт здесь.
- Договор «ИИ ↔ конструктор» — EXCHANGE_SPEC.md (из ai-dialog-start). Меняется только решением в журнале, по согласованию с Modulero. Несовместимое изменение — новая старшая версия договора.
- Код modulero-next этот проект не меняет. Репозиторий Modulero подключается только для чтения (стенд и сверка).

Режим работы: без API и без публикации (владелец, 2026-10-28)
- Claude API не подключается, ключ не заводится, запросов к api.anthropic.com нет. Роль ИИ из диалога играет Claude в треде проекта: отвечает по SYSTEM_PROMPT_DRAFT.md и меняет прототип только вызовами стенда (npm run dialog).
- Ничего не выкладывается на сайт и сервер Modulero. Прототип владелец видит на странице сеанса: файл HTML в папке проекта или частная страница Artifact.
- Подключение Claude API, окно на сайте и всё, что с ними связано (оркестратор, квоты на реплики, журналы на сервере), — только после отдельного решения владельца. До него эти области не открываются.

Автономность и вопросы владельцу
- Работа идёт без остановок. Мелкие вопросы (термины, тексты реплик, порядок сценариев, числа с пометкой (Д)) тред решает сам с пометкой (Д) и продолжает. Директор собирает их и присылает владельцу одним списком раз в день.
- Сразу владельцу — только то, без чего работа стоит или что нельзя отменить: любые расходы, подключение Claude API, выкладка чего-либо на сайт или сервер, изменение договора с Modulero.
- Формат вопроса: проблема → рекомендуемый вариант → обоснование → последствия. На время ожидания работа продолжается по рекомендуемому варианту, если шаг можно отменить.
- Юридические вопросы владелец решает сам; треды их не исследуют и не поднимают.

Параллельная работа
- У каждой области один тред-владелец; Директор называет его при выдаче задачи. Области: договор и инструменты; стенд с движком и сеансы; страница прототипа; системный промт и сценарии; разбор сценариев; инфраструктура и проверки.
- Треду, которому нужно изменить чужую область, Директор согласует порядок PR с её владельцем.
- Номера AI-DEC, диапазоны FINDINGS и версии договора выдаёт только Директор. Общие файлы (журнал решений, FINDINGS) — по файлу на запись; генерируемые файлы руками не правятся.

Задачи и PR
- Каждая задача — своя ветка от свежего main и один PR в main. Маленькие PR: одна мысль, примерно до дня работы. В main напрямую не коммитить.
- В описании PR: что сделано, как проверено (итог npm run check, SHA, версия Node, для промта и инструментов — итог сценариев, проигранных в треде), что осталось, решения для владельца, ссылка на задачу.
- Коммиты небольшие, сообщение по-русски, первая строка до 72 символов.

Проверки
- npm run check — быстрая проверка PR, не дольше 10 минут: типы, юнит-тесты, проверка схем инструментов, проигрыш записанных вызовов инструментов каждого сценария на стенде со сверкой версий и сумм (без ИИ и без сети). Должна закончиться строкой «All checks passed.» на Node 24 на точном SHA; итог, SHA и версия Node — комментарием в PR. Не пушить с красной проверкой.
- Сценарии с ИИ: при изменении системного промта или инструментов Claude проигрывает затронутые сценарии в треде (как ИИ из диалога), записывает вызовы в сценарий и итог (что совпало, где ошибся) — комментарием в PR. Набор с настоящим Claude API (npm run eval) появляется только после решения владельца о подключении API.
- Нестабильный тест или сценарий не перезапускать до случайного успеха: сообщить Директору, он заводит задачу на починку.
- Слияние: исполнитель PR не сливает. Сливает Директор после своей проверки и зелёного npm run check на SHA, который содержит текущий main; о слиянии сообщает владельцу. Проверяющий не повторяет проверку, если исполнитель выложил зелёный итог на том же SHA.

Ключи и расходы
- Ключей Claude API в проекте нет. Если для задачи кажется нужным API или платный сервис — вопрос владельцу через Директора, а не обходной путь.
- Когда владелец решит подключать API: ключ только в секретах среды и на сервере, никогда в коде, логах, PR и браузере; каждый прогон пишет токены и стоимость; лимит расхода задаёт владелец.

Данные людей
- В сценарии, сеансы и журналы стенда не записываются имя, телефон, email и адрес; в сценариях — только вымышленные данные. Сеансы стенда — рабочие файлы проекта, не журналы людей.
- Защита движка (MOD-DEC-497 Modulero): в ответах инструментов только то, что видно на экране конструктора; ставки, себестоимость, внутренние правила не попадают в ответ стенда и на страницу прототипа. Так стенд сразу готов к будущему API.

Препятствия
- Технический сбой обходится поддержанными средствами. Защитный запрет (политика среды, прокси, права, недоступный домен) не обходится: описать, какую настройку изменить и зачем. Ничего не скачивать и не ставить обходными путями.

Внешние материалы
- Библиотеки — с закреплёнными версиями и записью в docs/SOURCES.md. Модели Claude (когда дойдёт до API) — по идентификатору без даты (например, claude-opus-5-5).
