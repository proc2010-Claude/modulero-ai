Первая задача проекта «ИИ-диалог Modulero»: стенд без API и первые диалоги.

Цель. Разобраться, как работает идея, без ключа Claude API и без публикации на сайте. Роль ИИ из диалога играет сам Claude в треде этого проекта: владелец пишет в треде «Хочу кухню», Claude отвечает по правилам SYSTEM_PROMPT_DRAFT.md и меняет прототип только вызовами стенда, который выполняет правки движком Modulero. Владелец видит прототип после каждого ответа.

Что сделать:
1. Стенд движка — консольная команда в репозитории modulero-ai, например npm run dialog -- <инструмент> '<JSON>'. Она выполняет инструменты из examples/tools.claude-api.json (start_project, get_options, kitchen_edits, get_project, undo, variants) функциями ядра modulero-next. Репозиторий modulero-next подключён только для чтения, на закреплённом SHA (на старте cbaf1534) и выпуске каталога hw-2026-10-27.8. Образец вызовов — tools/kitchen-dialog-run.mts. Ответ — JSON по EXCHANGE_SPEC.md §5: applied, refused, not_run, state, price, warnings.
2. Сеанс на диске: папка sessions/<имя>/ — файл проекта каждой версии (.modulero), история версий с подписями правок, журнал вызовов и ответов движка, текст диалога.
3. Страница прототипа: после каждой правки стенд пишет одну HTML-страницу сеанса — превью версии (previewSvg), план, состав, цена со статусом «полная / неполная», история версий и лента диалога. Страница — файл в папке проекта; при желании владельца её показывают как частную страницу Artifact (видна только владельцу). На сайт ничего не выкладывается.
4. Режим «ИИ-диалог» для треда: короткая инструкция в CLAUDE.md репозитория — когда владелец пишет «Режим диалога», Claude отвечает как помощник по SYSTEM_PROMPT_DRAFT.md, вызывает только инструменты стенда, не считает сам и после каждой правки прикладывает страницу прототипа.
5. Сценарии кухни — 12 диалогов: прямая, угловая, П-образная, с островом; «Хочу кухню» без параметров и со всеми параметрами сразу; техника, которая не помещается; невозможный размер стены; смена материалов; «верни как было»; просьба назвать себестоимость; просьба «посчитай сам без конструктора». У каждого — реплики человека, ожидаемое состояние (по сводке), ожидаемые отказы движка и критерии ответа.
6. Проверка стенда без ИИ: npm run check проигрывает записанные вызовы инструментов каждого сценария и сверяет версии и суммы. Пример из EXCHANGE_SPEC.md §6 должен дать те же KPR2-… и суммы, что в examples/kitchen-dialog.log.json.
7. Разбор: Claude проводит 12 сценариев в треде (как ИИ из диалога) и записывает, что получилось: где хватило вопросов, где ИИ ошибся, каких правок или данных движка не хватило, что неудобно человеку.

Готово, когда:
- владелец сам проходит в треде «Хочу кухню» от первого вопроса до угловой кухни и видит страницу прототипа после каждого ответа;
- ни в одном сценарии не названа цена, которой нет в ответе стенда, и не скрыта неполнота цены;
- npm run check зелёный на Node 24, итог — в PR;
- владельцу — короткий отчёт: что получилось, что мешает, список задач MOD-AI для Modulero, предложение по следующему этапу (шкаф, купе, другая мебель) и по тому, когда имеет смысл подключать Claude API.

Чего не делать: не подключать Claude API и не заводить ключ, не выкладывать ничего на сайт и сервер Modulero, не менять код modulero-next. Если на стенде не хватает функции ядра для правки из договора — записать как задачу MOD-AI-N, а не писать замену.
